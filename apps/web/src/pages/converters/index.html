Converters

Convert between JSON, XML, CSV and text, and encode or decode Base64, hex and URLs. Everything runs in your browser.

Choosing a converter

Use the structured data converters to move data between JSON, XML, CSV and plain key-value text. Use the encoders when text needs to be written in Base64, hexadecimal or percent-encoded form, for example in APIs, logs or query strings.

  • JSON to XML turns nested objects into nested elements. Use it to build XML from a JSON sample.
  • XML to JSON turns elements into object keys. Attributes are kept with an @ prefix.
  • JSON to CSV turns an array of objects into a spreadsheet file, quoting values where needed.
  • CSV to JSON uses the first row as the keys. Quoted fields that contain commas are not supported.
  • Text to JSON and Text to XML turn key: value lines into structured output.
  • Base64, hex and the URL encoder encode and decode text.

Every converter runs in your browser, so the data you paste is not uploaded to Toolpad.

Which format should you use?

JSON suits web APIs and configuration files. XML suits documents that need namespaces, attributes or a strict schema. CSV suits flat tables that spreadsheets open directly. Plain key-value text is the simplest starting point when you are typing data by hand.

Converting between formats can lose information. JSON has no attributes, so attributes in XML become element text or are dropped. CSV has no types, so numbers and booleans become text unless a converter infers them. Check the output of each converter against the rules described on its page before you use it in a pipeline.

A checklist before you convert

  • Check that the input is valid for its format. A JSON converter cannot read unquoted keys, and a CSV converter cannot read a file with a missing header row.
  • Check the output against a small example before converting a large file.
  • Keep the original file. Conversion does not change your input, but the output may lose information that the source format held.
